# UI: the mechanism

Part of [ui.md](../ui.md); how to read the tables is said there. Links and joints, the pose and its sliders, the view in the pose (D49), the drive of a joint (D59).

## The mechanism (D49)

| Function | Command / call | Reads |
|---|---|---|
| The tree of links and joints | | `document.mechanism`; `evaluation.mechanism` of the shown state: `roots`, `links[id].bodies`, `.missing`, `.blockedBy`, `joints[id].status`, `.error`, `.fieldErrors`, `.value`, `.lower`, `.upper` |
| The bodies in no link | | `evaluation.mechanism.unassigned` |
| Make or change a link | `setLink { id, name, bodies }`; a body taken from another link: a `batch` with `setLink` of that link first | the bodies of the whole model |
| Remove a link | `removeLink { id }`; refused while a joint names the link (the reason in the status line) | |
| Make or change a joint | `setJoint { id, joint }`: the joint of 5a whole in the input form, the drive as a patch (an emptied drive field of a joint being changed is sent as `null`, since a field left out is kept) | `JOINT_FIELDS[type]` for the numbers of the pose, `JOINT_DRIVE_FIELDS[type]` for those of the drive; the sketches of the document for the axis |
| Remove a joint | `removeJoint { id }` | |
| The value of a joint (a number or an expression) | `setPose { values: { [joint]: number or expression } }` | `joint.expressions.value`, `JointResult.value` |
| Drag the slider of a value | `preview(setPose, marker)` while dragged, `execute(setPose)` when released | `JointResult.lower`, `.upper` |
| Reset the pose | one `setPose` with every value that has no expression | the limits of every joint |
| The view in the pose | UI state (the transform of a link on the meshes of its bodies) | `evaluation.mechanism.links[id].transform`, `.blockedBy` |
| A query as modelled | `engine.query(name, args, { at, geometry: 'modelled' })` | |
| New IDs of links and joints | UI state (`newId('link')`, `newId('joint')`) | the links and joints of the document besides the IDs it already counts |

- **The panel** *Mechanism* is the last section of the model panel, shown once the model has a body or the document has a link. Without a link it says in one line what links and joints are. The tree starts at the roots (the links that are no joint's child); under a link are the joints whose parent it is, and under a joint its child link. A link shows its name and ID, its bodies by name (a body the model does not have is marked *missing* and explained in a warning: a body made under that ID will be in the link) and, when a joint nearer the root has no motion, a warning that it is drawn with that joint at zero and that a query about its bodies fails. A joint shows its name and ID, its kind and its axis, and the issue of the engine when it is in error (a broken axis, an expression in error, limits that cross, a value out of its limits after a change of a parameter). The bodies in no link are listed below the tree. *Edit* and *Remove* are on every link and joint.
- **The value of a joint** (not of a fixed joint) is a field that takes a number (an angle in degrees, a travel in millimetres) or an expression over the parameters (radians), with the value of an expression next to it; leaving the field sends one `setPose`. A number removes the expression of the value, and with it a coupling. Under it is a slider between the limits (the numbers the limits have now, also when they are expressions). Dragging it previews the pose at the marker: the view shows the preview, the document is not changed, the field follows the slider and nothing else of the panel is built again. Releasing it sends one `setPose`, so a drag is one step of undo. The slider of a value with an expression is disabled (its title says how to set the value by hand), and so is one whose limits cross.
- **A continuous joint** has no limits; its slider spans a turn either way (±180°), widened to the value when the value is beyond.
- **Reset pose** sends one `setPose` with every value that has no expression and is not already there: zero where the limits contain it, else the limit nearest to zero. A joint whose limits cross is left out. A value with an expression is left as it is. The button is disabled when no joint has a value without an expression; when nothing would change the status line says so.
- **The form of a link** has *ID* (generated, `link<n>`, fixed when the link is changed), *Name (empty: the ID)* and a checkbox per body of the model, with the bodies the link lists that the model does not have marked *missing*. A body in another link says *moves from …*; confirming then takes it out of that link in the same command. *OK* sends one command; a refused command keeps the form open and the status line says why.
- **The form of a joint** has *ID* (`joint<n>`), *Name*, *Kind* (revolute, continuous, prismatic, fixed), *Parent link*, *Child link (moves)*, the axis (not for a fixed joint: the picker of the pattern form, a base axis, the normal of a sketch plane through a point of the sketch, or a line of a sketch (D58), over all sketches of the document) and the numbers of the kind: *Lower limit*, *Upper limit* and *Angle* or *Travel*, each a number or an expression. A new joint starts as revolute about Z, its parent the first link and its child the first other link that hangs on no joint, with −180° to 180° and 0 (a prismatic joint 0 to 100 mm and 0). Another kind keeps the numbers as typed while the unit stays and starts from the defaults of the kind otherwise. *OK* sends one `setJoint` with the whole joint; a field left empty is refused in the app. Under the numbers of the pose are the four fields of the drive of the kind (D59, read only by the export of a robot; a hint says so and that URDF needs the effort and the velocity of a revolute or prismatic joint): *Effort* (N·mm, N for a prismatic joint), *Velocity* (rad/s, mm/s), and for a revolute or continuous joint *Rotor inertia* (g·mm²) and *Gear ratio*, each optional, a number in its own unit as typed (a velocity is not converted from degrees) or an expression. A changed kind keeps a typed drive field the new kind has in the same unit (revolute and continuous share all four; a prismatic joint starts with an empty drive). An empty drive field is left out of a new joint and sent as `null` for a joint being changed. A drive field with an expression of a joint being changed shows its value, or `= ?` with the reason when it does not evaluate; the row of the joint in the tree then has a warning that names the field and says that the export of a robot refuses the joint (the pose is not blocked).

## The view in the pose (D49)

- In the **model mode** the view shows the pose of the mechanism of the shown state: each body is drawn where the transform of its link puts it, without new geometry (the mesh gets the transform). Its outline, its highlighted faces (of the selected feature, of the selection, of a picked collision or gap, of a print orientation), its selected edge, the box the camera is fitted to (*Zobrazit vše*) and the pick in the view follow it; the face and the edge a pick names do not depend on it. What a view of a query adds as coordinates of its answer (a measured distance, the cut of a section, the points of a gap) is in the pose already.
- **At the marker** the view shows the state at the marker with its own mechanism: a link whose bodies are not made yet lists them as missing.
- **A blocked link** (a joint on its way to the root has no motion) is drawn by its transform, which counts that joint as standing at zero, and marked in the view with a label `not posed: <joint>` at the top of each of its bodies; the status line names the joint and its issue.
- **In a sketch and in the form of a feature** the view shows the model as modelled, because sketches, planes and the references of features are there. So does the model mode while the answer of a query asked *as modelled* is shown, or the answer of a query that always answers as modelled (the print check).
- **The status line** says which of the two is shown whenever the document holds a pose (a link that is moved or blocked): after the note, *The view shows the pose of the mechanism.* (with the blocked links), or *The view shows the model as modelled* and why. A document without such a link says nothing.
- **A picture** saved by the button draws the bodies where the view draws them; a picture taken by the AI (`view_image`) draws the pose the state holds, also a state that is not written (`at` and `after` on the path of every operation, D59: `after: setPose` draws a pose without writing it). A blocked link is drawn there as in the view, with its joint at zero, and the answer names the joint (`about.blocked`); with a section such a body is refused.
- **The collisions** and every other query are asked about the state shown, so in the pose. A body that cannot be posed fails the query, and the form shows the message of the engine, which names the joint. The form of a query offers *As modelled* while the shown state holds a pose; ticked, the query is asked with `geometry: 'modelled'`.
- **Status line of an ID used again**: a command of the app that adds a feature or a sketch entity under an ID the mechanism still names (a body of a link, the sketch, the point or the line of an axis) says so, as for body properties; the generator of IDs does not hand such an ID out.

### Implementation status

Implemented and merged 2026-11-16; driven by `packages/app/test/app.test.ts` (snapshot `mechanism.txt`): two links and a joint made in the panel, the slider previewed and released (one step of undo), a pick of a turned body, a picture in the pose, the collisions in the pose and as modelled, a highlighted pair in the pose, a sketch shown as modelled, a value by an expression, a value out of its limits that blocks the link, reset pose, the marker, a removal refused, the form of a joint filled in from the document. The picture and the text of an ID used again have unit tests (`picture.test.ts`, `issue-text.test.ts`). Run in a browser on 2026-11-16 on two blocks and a revolute joint about Z: the turned body and its outline, *Zobrazit vše* fitted to the pose, the slider previewed and released, a pick of the three.js view on the turned body, a picture fitted to the pose. The drive (D59, 2026-11-17): the four fields filled in, sent in one `setJoint`, read back into the form, an emptied effort sent as `null` (the rest kept), the fields kept across revolute and continuous and dropped for prismatic (snapshot `mechanism.txt`, steps 28 to 34, with an effort whose parameter is removed: the warning in the row and the note in the form). The export form lists the formats `urdf` and `mjcf` from the catalog with no code of its own and saves their set as one ZIP (`export-form.test.ts`).

- Not offered: picking a body in the view into a link, a link or a joint dragged in the tree to another parent, an axis picked in the view, the axis of a joint drawn in the view, a sweep of a value with the collisions at every step (the AI sweeps through the tool `query` with `after`), the pose of a preview of a feature form.
